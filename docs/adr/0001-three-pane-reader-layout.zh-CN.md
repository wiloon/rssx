# 三栏阅读器布局

> 本文件是 `0001-three-pane-reader-layout.md` 的中文版本，内容与英文版保持一致。以英文版为准。

## 状态

accepted（已接受）

## 背景

当前 UI 以三个整页路由的方式逐级下钻：
`FeedList`（`/`）→ `FeedNewsList`（`/feed-news-list?feedId=`）→ `News`
（`/news?newsid=&feedid=`）。从一篇文章回到 Feed 列表要靠浏览器后退，Feed 列表和文章
列表永远不会同时可见。这和所有主流桌面 RSS 阅读器（NetNewsWire、Reeder、Feedly、
Inoreader、Miniflux）都不一样——它们都是三个常驻的纵向栏目：Feed | 文章 | 阅读区。

## 决定

用一个常驻的三栏布局取代逐级下钻的"一次一个路由"模式：

- **左栏 —— Feed 栏。** "All 视图" 加上一份平铺的已订阅 Feed 列表，每项带未读数。选中某个
  Feed 驱动中栏。
- **中栏 —— 文章栏。** 选中 Feed 的文章，最新在前，未读用正常字重、已读置灰。选中某篇文章
  驱动右栏。
- **右栏 —— 阅读区。** 选中文章的标题、时间、来源、以及 Feed 提供的内容（渲染为净化后的
  HTML），配"打开原文"和上一篇/下一篇控件。

选中状态（`selectedFeedId`、`selectedArticleId`）存在 Vuex/Pinia store 里，同时同步到
URL query，这样刷新页面和分享链接都能还原同一个视图。三个路由组件合并成一个 `Reader`
视图；`/login` 和 `/register` 仍是独立路由。

在窄视口下，三栏退化为一次只显示一栏 + 栏间返回——就是现在的下钻，但改成布局内的状态而不是
路由历史。

### 文章栏沿用现有的"未读窗口" API

中栏由现有端点直接驱动，不做改动：
`GET /news-list`（从已读边界开始的一页未读文章）、
`GET /mark-read`（把边界往前推一页，返回下一页）、
`GET /previous-news`（往回退一篇）、`GET /news`（取一篇文章，副作用是把它标为已读）。

后果：中栏是一个**未读队列**，不是完整归档。你只能往前翻未读文章、往回退看已读过的文章，
但不能自由滚动一个 Feed 的完整历史。要做带随机访问的完整时间线，需要一个新的分页列表端点，
并弱化已读边界的作用；这一项是**推迟**，不是**否决**——见下方"考虑过的方案"。

`GET /feeds` 目前把每个未读数拼进 Feed 的标题字符串里（`"InfoQ - 12"`）。新布局需要未读数
作为独立字段。这是与本 ADR 配套的一个小的后端改动，不是重新设计。

## 考虑过的方案

- **保留下钻，只重做样式。** 最省事，但留下了促成这次改动的核心问题——没有并列的上下文、
  要靠后退键换 Feed。
- **现在就三栏 + 新的完整时间线列表端点。** 理想终态，但它会和布局改动同时重做已读状态模型
  （边界 + 乱序已读集合）。拆开做能让本次改动可评审；时间线可以在布局落地后单独出一个 ADR。

## 后果

- 深链形式变了：一个 `/reader?feed=&article=` 取代三个路由。旧书签会失效；对一个单用户自托管
  工具来说可以接受。
- 断言三个页面之间路由跳转的 E2E 测试需要针对布局内选中状态重写。
- "All 视图"（feed id `-1`）后端仍没有列表实现（`LoadNewsListByFeed` 对 `-1` 返回空）；
  左栏会显示它，但在补上该实现之前点进去是空的。
